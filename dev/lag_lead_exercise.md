# Exercise: faster `lag` and `lead`

A guided exercise, not a solution. It points at the code, names the constraints,
and asks questions. The answers and the code are yours.

## 1. Where things live

| What | Where |
|---|---|
| Implementation | `src/tablecloth/api/rolling.clj` (`lag`, `lead`) |
| Public export | `src/tablecloth/api/api_template.clj` (`export-symbols tablecloth.api.rolling`) |
| Generated API | `src/tablecloth/api.clj` — regenerated by `exporter/write-api!` in the template's `comment` block; never hand-edit |
| Tests | `test/tablecloth/api/rolling_test.clj` (midje) |
| Column API (no lag yet) | `src/tablecloth/column/api/` |

Today both functions call `tech.v3.dataset.rolling/rolling` with a fixed window of
`k+1`, `:edge-mode :zero`, and the `first` / `last` reducer.

## 2. The observation

`lag` is a positional shift: output row `i` holds input row `i-k`. No row needs
more than one input value, so nothing needs a window.

The rolling engine still builds a window per row and runs a reducer over it. Read
`apply-window-ranges` in TMD's `tech/v3/dataset/rolling.clj` and note:

- what `:datatype` the `first` / `last` reducers declare, and what `dtype/emap`
  therefore produces;
- where the result's datatype gets decided;
- whether the source column's missing set is read at all.

## 3. Primitives to look at

All in TMD 8.024 (`tech.v3.dataset.column`, implementations in
`tech.v3.dataset.impl.column`):

- `select` — a column restricted to a row range. What does it do to the missing set?
- `prepend-column-with-empty` / `extend-column-with-empty` — grow a column by `n`
  missing rows at the front / back. Read the bodies, not just the names:
  - Which datatype do they allocate? (Look for `packing/unpack-datatype`.)
  - How is the source missing set carried over in each? Why does one need
    `bitmap/offset` and the other not?
  - What do they write into the new slots, and where does that value come from?
- `new-column` (4-arity) — builds a column from data, metadata, and an explicit
  missing set without rescanning.
- `tech.v3.datatype.packing` — `packed-datatype?`, `pack`, `unpack-datatype`.

Clue: two of these, composed, are most of a lag. The interesting work is
everything around them.

## 4. Invariants to keep or decide on purpose

- **Positional.** Shifts by row, not by timestamp. Say so in the docstring.
- **Length.** Output length equals input length for every `k`.
- **Datatype.** Output datatype equals input datatype — including `:int64`,
  `:string`, `:boolean`, and packed temporals like `:packed-local-date`.
- **Source missingness.** A value missing in the source stays missing after the
  shift, at its new position.
- **Boundary.** Today numeric boundaries are `0` and object boundaries are `nil`.
  Check at the REPL whether that `0` is *recorded as missing*; it decides what
  "compatible" means.
- **`k = 0`.** Same column back? A copy? Does it matter?
- **Large `k`.** `k >= row count` — all boundary, or an error?
- **Invalid `k`.** Negative, non-integer, `nil`. What does the current code do?
- **Grouped datasets.** Does `tc/lag` on a grouped dataset shift per group today?
  Should it?

## 5. Benchmark context (indicative only)

From an exploratory run in tablecloth.time, lag by 1 on one million `:float64`
rows, median:

| Implementation | ~ms |
|---|---:|
| Tablecloth rolling `lag` | 46 |
| Former tablecloth.time lazy `concat` | 241 |
| Direct typed-column prototype | 5.3 |

One machine, one JVM, and the rolling row reproduced `tc/lag`'s body on **TMD
7.062**, not the 8.024 Tablecloth ships with. Use it to set expectations, not as
a claim. Re-measure here before you quote anything.

## 6. A trustworthy before/after

1. Keep a copy of the current `lag` body under another name in a scratch file
   outside `src/` so both run in one JVM.
2. Build inputs with a fixed seed: `:float64`, `:int64`, `:string`,
   `:local-date`, at 1e3, 1e5, 1e6 rows.
3. Force the result (read the last element) — readers can be lazy, and an
   unforced result measures nothing.
4. Warm up (iterations *and* at least a second of wall time), `System/gc`, then
   take 15+ timed runs. Report median, min, max.
5. Before timing, assert parity between old and new on values, missing set, and
   datatype. A fast wrong answer is the usual failure.
6. Print JVM version, heap, and core count with the results.

The `:dev` alias in `deps.edn` gives a REPL with Tablecloth on the classpath.

## 7. Prior art in tablecloth.time

Upstream `scicloj/tablecloth.time`, PR #67 (commit `14a92fc`, "Optimize lag/lead
and add explicit boundary :fill"):

- `src/tablecloth/time/column/api.clj` — `shift`, `lag`, `lead`, and private
  helpers for fill and packed datatypes. Column-level: takes a column, returns
  a column.
- `src/tablecloth/time/api.clj` — `add-lag`, `add-lead`, `add-lags`,
  `add-leads` (dataset-level, including multi-lag).
- `bench/lag_lead_bench.clj` — the benchmark behind section 5.

Suggestion: work through section 8 first, then compare. Differences are worth
more than matches — tablecloth.time defaults boundaries to *missing*; Tablecloth
today defaults numeric boundaries to `0`.
